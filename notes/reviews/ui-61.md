# Issue 61 sign-in critique and polish

Two independent assessments reviewed the live sign-in screen and screenshots at 390, 768, 1280 and 1440 pixels. Assessment A reviewed hierarchy, cognitive load and design specificity. Assessment B ran the deterministic detector and reviewed browser semantics, overflow, keyboard focus and console errors.

## Findings and applied polish

- P2: Google eligibility appeared after the action. Moved the linked-account explanation before the Google action and associated it with aria-describedby.
- P2: Hints were smaller than the design system floor. Raised them to 15px.
- P2: Blue footer links and uppercase eyebrow conflicted with the visual system. Applied an amber underlined link and removed the redundant eyebrow.
- P2: The primary mobile action did not span the available width. It now fills narrow screens and retains a 44px minimum height.
- P2: Heading weight and approval next-step copy were weak. Applied 800 weight and explicit Instructor approval copy.
- P3: Added restrained honey gradient/hover treatment with reduced-motion handling.
- P3 retained intentionally: The Sign in header remains on this page because the owner explicitly requested it on every page.

Assessment B's deterministic detector returned no findings. Browser inspection found one H1, named navigation, no horizontal overflow, visible amber keyboard focus and no console errors. The controls preserve native form semantics.
