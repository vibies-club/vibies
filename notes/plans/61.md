### Architecture and contracts

- Keep `app/` and the existing Next build/dev/start path for the source host and rollback. Add `frontend/` (React 19, existing Vite/React plugin) and `worker/` (fetch-native TypeScript). No new framework or client router is needed: ordinary anchors and native form navigation preserve existing behavior.
- Reuse the existing JSX, CSS, self-hosted fonts, images and synchronous project presentation components. This is a delivery change, not a new screen or design direction. Existing screenshots are the visual reference; repeat four-width inspection and Impeccable critique/polish after conversion.
- Serve public static HTML/assets from Workers Static Assets. The browser loads a static React shell; private data only arrives from authenticated JSON. Never embed private data, credentials, environment values, provider tokens or raw domain results in build output. Client guards are presentation only.
- A fixed `GET /api/page?path=...` bootstrap endpoint accepts only the nine existing page routes and known query parameters: `/`, `/demo`, `/sign-in`, `/access-denied`, `/welcome`, `/admin/members`, `/projects`, `/projects/connect`, `/projects/:uuid`. It returns a validated discriminated DTO with `access`, `googleEnabled`, optional `redirect`, and the one page's authorized data. No arbitrary operation names, SQL, environment IDs or browser-provided identity are accepted. Use no-store and same-origin JSON; no CORS exposure. Other API paths are 404 and methods 405.
- DTO page fields: `demo` (public sample only), `linking` (linked/canLink booleans), `members` (Instructor-only validated account projection), `projects` (validated own/community projection), `project` (validated role-dependent detail), `connect` (installation URL/status/eligible id-name options only after explicit refresh=yes). Page paths and redirects are validated against the fixed route set. Display failures using existing Retry content and discard stale private payloads.
- Frontend modules import only shared types and browser-safe presentation/validation. They must not pull Next, server-only, node:crypto, PostgreSQL, D1, Better Auth, credentials or provider calls into assets. JSON contracts use type-only imports or a pure shared module.
- The Worker directly reuses access-core, project-core, project-github, D1 adapters and the restricted fetch-native Google implementation. Do not import Next adapters (access.ts, access-http.ts, projects.ts, domain.ts, google-auth/server.ts) into the Worker. Move reusable result validators into a pure module without changing their behavior.
- Construct request-local services from explicit env bindings. Validate configured origin; do not assign request env to global process.env. Check the D1 activation state/environment before every operation, with at most request-local memoization. Enforce the existing read-only allowlist and D1 atomic authorization guards. Fail closed for missing/disabled/reconciled/wrong-environment activation. Sign-out still clears browser cookies on failures.
- Keep native form routes and behavior: GET /auth/browser, POST /auth/start, GET /auth/callback, POST /auth/sign-out, POST /auth/google/start and /link, GET /auth/google/provider/callback/google, POST /projects/action, POST /admin/members/action. Preserve bounded form parsing, origin/content-type checks, PKCE/browser binding, one-use state, rotation/expiry, grant hooks, recent GitHub linking, no public Google signup, provider verification provenance, optimistic versions, limits, error allowlists and 303 responses. Unknown provider paths never expose the generic Better Auth handler.
- Preserve return to an opened private page after sign-in using an HttpOnly short-lived same-origin return cookie validated against only the known private paths (UUID-only project IDs, no arbitrary host/query). Browser state is not an authorization source. Invalid values fall back to /welcome; consume/clear the return cookie after successful login and sign-out. Link Google returns to /welcome.
- Keep the staging artifact contract `dist/client/` plus default `dist/server/index.js.fetch`; build the static frontend and standalone bundled Worker into that layout without executing candidate code in trusted deploy jobs. Trusted staging and preview wrappers retain authoritative receipts. Update their fixed asset routes to allow static `/assets/*`, fonts and images through while routing API/auth/actions/identity to the Worker. Unknown APIs/assets must not fall through to a 200 HTML response.
- Change Cloudflare-only build commands in CI, preview/staging build jobs and Workers Builds to the static build. Leave Next source-host commands intact. Production stays disabled until all existing migration gates pass. Document the choice and remove unused Cloudflare SSR deployment dependencies only once the replacement builds/proves successfully.
