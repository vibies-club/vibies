## Gate 4: Google linking while preserving GitHub access

Use Better Auth with D1 only as a Google identity subsystem; keep existing GitHub OAuth routes and Vibies session semantics. Add a unique private mapping between a random Better Auth user ID and the existing GitHub account. Do not infer identity from matching email, username or nickname. Synthetic shadow-user addresses, if required by Better Auth, use a unique .invalid address and remain private.

Configure Google disableSignUp and disableIdTokenSignIn; account linking enabled, disableImplicitLinking true, allowDifferentEmails true only for explicit authenticated linking, updateUserInfoOnLink false. Disable password signup, password reset, email changes and provider auto-registration. Pin the Better Auth version and use its documented plugin endpoints to create a short-lived bridge session after a same-origin POST with recent GitHub proof. Isolate version-sensitive adapter/cookie helpers and cover them with integration tests.

Better Auth retention is deliberately minimal: store only the stable Google subject and its random internal mapping; use synthetic shadow profile names/addresses, never real Google profile data. Suppress persistence of provider access, refresh and ID tokens after callback verification, and disable IP/user-agent retention. An unavoidable transient token must remain in request memory only. Bridge sessions expire within five minutes, are single-purpose, HttpOnly/Secure/SameSite cookies and are removed after linking. Inspect actual stored rows after linking, login, refresh and failure; test alternate account-management endpoints against these restrictions.

At link start and callback/account insertion, validate an unexpired single-use authorization bound to the exact Vibies user, recent GitHub-authenticated session and approved membership. Deny concurrent/replayed linking, conflicting provider ownership and revoked/expired sessions. Block generic linking/unlinking API bypasses. An existing Google identity can never be silently reassigned.

After Google login, resolve only an already-linked identity, recheck current membership, and issue the existing Vibies session with Google provenance. Do not call the GitHub finish_sign_in upsert path for Google. Sign-out must end both relevant sessions. A Google-authenticated session cannot authorize changing the Google link without a fresh GitHub login. Test unlinked Google, email collision, revocation during OAuth, replay and cross-account attacks.

Browser-configure a Google Cloud project, consent screen and Web client with exact local, synthetic-preview and final Workers callback URLs. Do not enable billable products or accept a card request. Pause for human account creation/login and for explicit permission to perform the user's live Google authentication. Transfer secrets directly from page to wrangler secret put stdin without printing, chat values, repo files or persistent plaintext. .dev.vars.example contains names only; no .env reads.

Deployment activation is a database state machine, independent of a build: disabled -> reconciled -> active. A fresh production database and every automatic deployment default to disabled. Store the activation record in D1; application code must verify it before serving private reads or any writes, and builds cannot alter it. Pin the working Vercel source deployment and disable automatic production promotion for this migration before the Instructor merges. Order: deploy disabled Cloudflare code, prove synthetic staging, impose and verify the source barrier, take final snapshot, import/reconcile, record reconciled, explicitly activate destination, verify, then switch traffic. Subsequent builds preserve the existing activation state. Test that a new deployment cannot bypass disabled state. Keep the pinned source read-only after activation; rollback of code on Cloudflare preserves the same D1 and activation record.

Rollback before destination writes: release old write barrier and resume old host. After destination writes: never point back to stale Supabase blindly; capture destination delta, reconcile it into the source under a barrier, verify, then switch. Source deletion and subscription cancellation are excluded.
