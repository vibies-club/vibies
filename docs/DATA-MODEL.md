# Demo Data Model

[Documentation home](../README.md) · [Supabase setup](SUPABASE-SETUP.md) ·
[Product domain](DOMAIN.md) · [Decisions](DECISIONS.md)

Issue #13 uses one small Supabase table to prove a public read from the deployed
application. Every value in this table is synthetic demo content.

## Boundary

`public.demo_projects` is separate from the Vibies `Project`, `Personal Project`,
and `Class Project` concepts in the [product domain](DOMAIN.md). It does not
define the future product schema. Do not put member data, repository data, real
projects, names, contact details, credentials, or other personal data in it.

This demo has no authentication, write feature, ORM, repository integration, or
real product data. Private access is implemented separately under
[D-014](DECISIONS.md#d-014-use-direct-github-oauth-and-a-private-database-api).

## Table

| Column | PostgreSQL definition | Purpose |
| --- | --- | --- |
| `id` | `bigint GENERATED BY DEFAULT AS IDENTITY (START WITH 2) PRIMARY KEY` | Stable row identifier. Automatic IDs start at 2 so the seed can keep ID 1. |
| `title` | `text NOT NULL` | Required synthetic title. |
| `summary` | `text NOT NULL` | Required synthetic summary. |
| `created_at` | `timestamptz NOT NULL DEFAULT now()` | Creation time assigned by PostgreSQL. |

The setup SQL preserves exactly one sample row with `id = 1` when it runs again.
The application reads only this fixed row.

## Access

Row Level Security is enabled. One `SELECT` policy applies to the Supabase
`anon` role. That role receives `SELECT` access only. It cannot insert, update,
or delete rows.

The `authenticated` role intentionally receives no grants or policies in this
demo. Private product access uses the separate server-side access API described
in D-014; signing in does not change the public demo's grants.

## Application behavior

The `/demo` page creates an unauthenticated Supabase client with the public URL
and publishable key. It reads `public.demo_projects` for `id = 1` with uncached
runtime data. The page shows the row, an empty state when the row is absent, or
an error state when configuration or the query fails.

The authoritative SQL is [demo-projects.sql](../supabase/demo-projects.sql).
The metadata proof is [check-demo.sql](../supabase/check-demo.sql).
